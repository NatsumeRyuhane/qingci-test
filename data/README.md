# data/

| 目录 | 内容 | 是否提交 |
|---|---|---|
| `raw/` | 原始样本表格，保持收到时的原样 | **否** |
| `interim/` | 导入步骤产出的已解析、已清洗线程 | **否** |
| `processed/` | 由 `interim/` 构建的切分结果（`split.json`，含线程 ID）、知识库（`kb/`：模板候选、LLM 标注的缓存、模板草稿、审核文件和覆盖层、评测用的标准答案，含客服回复原文）和索引 | **否** |

只有本 README 和各个 `.gitkeep` 文件受版本控制，其他内容都由脚本重新生成。

## 获取样本数据

表格 `脱敏数据2026.2.10.xlsx` 由客户随测试题提供（[docs/requirements.md](../docs/requirements.md)），不在本仓库中。请向仓库所有者索取，并放到：

```
data/raw/脱敏数据2026.2.10.xlsx
```

## 备份审核结果

`processed/kb/overlay.json`（所有者的审核结果）和 `processed/kb/review_decisions.jsonl`（审核工具的决定）是人工劳动的成果，**不能重新生成**，但同样含有客户原文、不能提交。请在仓库之外备份（提案 0003 §12）。其他文件都可以用 `copilot` 命令重新生成。

## 规则

- 数据虽已脱敏，但仍属于客户。**永远不要提交**，在 issue、PR、提交信息或日志中也只能引用简短片段。
- 把数据发送给项目配置的 LLM 服务商属于产品功能本身，没有问题。但不要上传到任何其他外部服务（粘贴板网站、公开 notebook、其他 AI 工具的文件上传等）。
- 数据的具体情况见 [docs/data.md](../docs/data.md)。
